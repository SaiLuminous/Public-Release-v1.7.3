Publication notes — v1.8.3
Author: SaiLuminous
Original mod author: Anixx

Review adjustments:
1. Removed the unload size-wait loop, minimum-size bookkeeping, and polling.
   Subclasses are detached after in-flight attachments finish.
2. Removed ShowWindowAsync hooking entirely so it cannot introduce a blocking attach.
3. Retained the optional File Pilot override at the author's request. Documented the exact supported build, planned maintenance alongside releases, and why an app-specific hook is necessary. The reviewer's portability concern remains: this is still build-pinned, not a cross-version pattern scan.
4. Separate submission rationale: this mod deliberately targets eligible windows
   across applications, while the original is scoped to Explorer. Keeping them
   separate lets Explorer-only users retain that narrower scope. Shared mechanism
   and original authorship are explicitly credited. This rationale is subject to
   the maintainer's judgment; it does not claim the underlying technique is new.

Also replaced raw hook casts with typed hooks, simplified tracking to a set,
removed dead fields, and cleaned up documentation and indentation.
Version remains monotonic at 1.8.1 so existing local installations can update.

Validation:
- x86 and x86-64 compiler checks: run after changes.
- Actual enable/disable/update testing with apps remains pending.
- Removing size polling does not guarantee that an unresponsive window thread
  cannot delay synchronous subclass detachment.

Submit only mods/application-windows-no-min-size.wh.cpp to the official collection.
Do not describe the earlier runtime hangs as proven fixed before live validation.

1.8.1: Adds timed window-subclass detach attempts, normal close requests on blocked cleanup, and one manual-close prompt per process. No force termination. Uses WindhawkUtils internal removal-message protocol. Runtime validation is pending; later engine hook-removal waits cannot be detected by this fallback.

1.8.3: Restores normal close requests for undersized windows using observed native and File Pilot dimensions. After three seconds, one popup per process requests manual closure. No indefinite size-based polling; cancellation is respected if callbacks detach successfully. Live validation remains pending.

Version 1.8.3 judges size using the current visible rectangle; minimized and maximized windows are excluded from size-based closing. Cleanup-timeout prompts remain possible at any size and now state their exact reason. A close request is not forced termination, and apps can require confirmation or decline it. Runtime validation is pending.

1.8.4: Replaces fixed File Pilot timestamp/image-size/RVA checks with a unique executable .text pattern match. Wildcards cover both object-field offsets and the final IAT displacement. Return address is derived from the match end. Missing/ambiguous patterns fail closed; other releases have not been live-tested.

1.8.5: Consolidates executable-name lookup at initialization, adds a credited visual from the original mod, removes repeated README caveats, wraps text, fixes heading spacing, and documents late attachment. User-facing docs no longer contain test-status notes. Actual unload/runtime validation remains pending; the existing close/popup behavior is unchanged.

1.8.6: Corrects the embedded README closing marker so Windhawk can display Details. No runtime behavior changed.
